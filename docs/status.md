# Implementation status

What is built, measured against `docs/spec.md`. Updated with each slice.

## Works, tested end to end on a fresh Ubuntu 26.04 VM

`test/vm/run.sh` installs on a throwaway Multipass VM and runs `test/e2e/smoke.sh`, then installs a second time and runs it again.

- `install.sh --answers FILE`: installs Docker and ZFS, initialises Swarm, creates the ZFS pool, generates secrets, deploys the system stack in order and creates the Gitea admin account. Safe to run again.
- System stack: Postgres, Traefik, Keycloak (`auth.<domain>`), Gitea (`git.<domain>`).
- Controller CLI: validates a stack file, claims its hostnames, creates its ZFS datasets and Swarm secrets, and deploys it to Swarm behind Traefik.

## Differs from the spec for now

| Spec | Now |
| --- | --- |
| Setup wizard in a bootstrap container | Answers file only; no wizard |
| Let's Encrypt wildcard via DNS challenge; Pebble in tests | Self-signed wildcard certificate generated by the installer |
| ZFS pool on a drive | A sparse file on the root disk, unless `POOL_DEVICE` is set |
| Controller runs in the system stack and watches Gitea | A CLI on the host, run by hand |
| Private environments sit behind the Keycloak login | Private environments deny every request |
| Hostname claims come from Git | Kept in `/var/lib/homecloud/claims.json` |
| Gitea with Actions runner and registry | Gitea only |
| Tests with and without a second virtual disk | One disk; Multipass cannot attach a second |

## Not started

Keycloak as the login for Gitea and private environments, the controller as a service (Git watching, snapshots, SOPS, change records, approvals, restore), agent orchestrator, platform UI and chat, monitoring, alerts and ntfy, Sanoid and restic, coding-agent sandbox, Playwright tests.
